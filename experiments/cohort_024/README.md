# Cohort 024: three-lineage measurement and precision matrix

Prepared locally before any inference. The 1,472-task development fixture has eight new SCM families. It crosses causal direction, evidence agreement, physical source order, A/B source name, answer-alternative order, and two response contracts (semantic action versus neutral `X=0`/`X=1`) for both causal decisions and numerically matched noncausal scorecards. It also contains governing-source selection, randomized-only decisions under both contracts, and single-rate numerical checks. Each arm receives exactly the same frozen schedule. This is a **development measurement screen**, not confirmation of causal-specific damage or a quantization effect.

The CLI supports any explicit F16 plus selected GGUF quantization variants per lineage. The suggested fixed set is Qwen2.5-7B-Instruct, Mistral-7B-Instruct-v0.3, and Llama-3.1-8B-Instruct at F16, Q8_0, Q6_K, Q5_K_M, Q4_K_M, Q3_K_M, Q2_K. Do not add or remove arms based on initial outcomes. Models and their source revisions must be pinned in `sources.local.json` on the lab PC. All quantized variants should be produced from the corresponding F16 GGUF with one pinned `llama-quantize` binary. The model files and build logs stay outside Git; the run plan records their hashes.

The analysis reports strict validity, cell-level accuracy and action rates, plus family-paired within-lineage F16-versus-quantization accuracy contrasts. It does not auto-promote a positive result to a confirmatory claim. Assess component/control competence and task-frame stability before defining a prospective primary estimand. A common answer-order effect, source-selection failure, or harmful-direction matched-control failure blocks a causal-specific interpretation. The model family is treated as a fixed checkpoint factor; three checkpoints do not justify population inference about all LLMs.

See [lab runbook](../../docs/COHORT_024_LAB_RUNBOOK.md) for exact unattended commands, monitoring, recovery and Git checkpoints.
